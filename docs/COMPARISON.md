# 选题、相关项目与独立价值

## 实际用途和证据

1. 财务人员导出本单位完整任职期工资和实扣历史，比较逐期税额，定位多扣或少扣的记录。
   examples/audit.csv包含4期合成记录，退出1并定位E001第3期150元差异；
   audit-clean.csv修正后退出0。复核依据使用真实输入的此前已扣累计，支持后续补扣。
2. 薪酬软件开发者依赖MoonBit公共包，把计算逻辑放进本地或浏览器程序；
   examples/embed只消费pub接口，CI构建，避免把JSON文件读写层当作计算内核。
3. 系统迁移或参数变更时把CSV和期望结果加入CI。差异的退出码和稳定JSON允许阻止未说明的结果变化。

以上为已实现的接入方式与合成验证，尚无经核实的生产用户、企业采纳或税务机构认证。

## 相关项目比较

核对2026-10-29。以下依据各项目公开README，未声称完整测试对方代码：

| 项目 | 已有能力 | WageKit如何定位 |
| --- | --- | --- |
| [TaxCalculatorWeb](https://github.com/WingkySky/TaxCalculatorWeb) | 浏览器工资个税、累计、奖金比较、批量Excel等 | 承认业务重合；聚焦MoonBit依赖接口、实扣历史复核和可复现回归 |
| [SalaryCalculator](https://github.com/Ignareo/SalaryCalculator) | 累计预扣、五险一金、奖金、CSV等 | 不宣称“普通计算器做不到”；提供独立MoonBit内核和复核证据 |
| [mooncakes.io](https://mooncakes.io/)现有金融/金额包 | 表示、格式化或其他金融计算 | 不以关键词检索证明全生态不存在同类或“首个” |
| JoinWitness/Relcore | 本人既有数据关系项目 | 本项目领域和核心实现不同，没有把旧功能换名提交 |

整数分、累计预扣、二分反推均为常规方法，不作为算法首创。独立工作是把规则边界、
实际已扣状态、年度完整性声明、错误输入处理和复核接口整理为可依赖的MoonBit组件，
由库、CSV工具和浏览器共享实现。未复用以上相关项目的源码。

## 与驳回意见的关联

Relcore反馈涉及适用场景、功能重合和技术价值。WageKit用工资表复核和系统回归给出
可以执行的使用链路，公开承认现有计算器的能力，用独立复核接口和测试说明贡献。
这增加了可评估证据，不代表评委已经认可，也不能保证初审或奖项。
